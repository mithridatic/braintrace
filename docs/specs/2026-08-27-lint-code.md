# Lint code

## Status

Awaiting approval before implementation.

## Problem

The repository contains 192 inline lint and type-check suppressions in 75
tracked Python files:

- 68 suppressions in `braintrace`
- 121 suppressions in `examples`
- 3 suppressions in `docs/diagnostics`

The suppressions use `noqa`, `ruff: noqa`, `type: ignore`, and
`pyright: ignore`. The repository does not define Ruff or BasedPyright settings
and does not install either tool in `requirements-dev.txt`. The existing lint
and type gates are flake8 in pre-commit and mypy in CI.

The repository also contains 14 `pragma: no cover` markers. These markers
control coverage measurement. They are not lint or type-check suppressions and
are outside this change.

The 2026-08-27 execution workspace does not have Python lint, type-check, or
test tools installed. The implementation must add the declared development
tools before it records the full diagnostic baseline.

## Required behavior

1. Preserve public behavior, wire formats, persistence formats, validation,
   security, provenance, and reproducibility controls.
2. Remove every tracked Python `noqa`, `ruff: noqa`, `type: ignore`, and
   `pyright: ignore` suppression.
3. Fix the reason for each suppression with direct imports, explicit types,
   narrower interfaces, or clearer test fixtures.
4. Add Ruff and BasedPyright as explicit development checks with repository
   configuration.
5. Keep the existing flake8, mypy, repository-convention, and test checks
   clean.
6. Do not change JAX compilation boundaries, Brainstate transform use, or
   random-number generation.
7. Preserve unrelated work, including the existing mode change to
   `docs/make.bat`.

## Implementation plan

1. Add Ruff and BasedPyright development dependencies and define the smallest
   repository-wide settings that match supported Python versions and current
   source layout.
2. Add a repository-convention test that fails when a tracked Python source
   contains a lint or type-check suppression. This test prevents regressions.
3. Run Ruff, BasedPyright, flake8, and mypy to collect the complete baseline.
4. Fix diagnostics in small groups. Prefer shared typed helpers when several
   sites have the same cause. Do not add replacement suppressions or silent
   fallbacks.
5. Add focused sibling tests before any behavior-affecting fix. Keep pure
   annotation and import-order fixes behavior-neutral.
6. Add Ruff and BasedPyright to CI or pre-commit so local and automated checks
   use the same policy.
7. Run the lint and type gates, the repository-convention test, focused tests
   for touched modules, and coverage for behavior-affecting changes.

## Acceptance criteria

- A search of tracked Python files finds no `noqa`, `ruff: noqa`,
  `type: ignore`, or `pyright: ignore` marker.
- Ruff reports no diagnostics.
- BasedPyright reports no errors or warnings.
- flake8 and mypy report no diagnostics.
- The repository-convention test passes.
- Focused tests pass and meaningful coverage for changed behavior stays above
  90 percent.
- Public behavior is unchanged.

## Edge cases and test cases

- Direct-script examples must still resolve their local helper imports.
- Tests that assert import failure must still fail for the requested missing
  symbol without an unused-import suppression.
- JAX compatibility imports must work across supported JAX versions without a
  type suppression.
- Array-like inputs must keep the same accepted ranks and failure messages.
- Dynamic Brainstate module constructors must keep names and state ownership.
- Intentionally invalid test inputs must remain explicit without weakening
  production signatures.
