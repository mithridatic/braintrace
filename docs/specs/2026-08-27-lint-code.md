# Lint code

## Status

Awaiting approval. Implementation requires approval.

## Objective

Make all checked Python code pass Ruff, BasedPyright, MyPy, Flake8, and the
repository convention checks without lint or type-check suppression directives.

## Scope

- Add explicit Ruff and BasedPyright configuration and development dependencies.
- Keep the existing MyPy, Flake8, and repository convention checks.
- Remove `noqa`, `type: ignore`, `pyright: ignore`, and file-level Ruff
  suppressions from Python source, examples, diagnostics, and tests.
- Replace each suppression with a direct import structure, a precise type,
  narrowing, a cast, or a typed invalid-test fixture.
- Keep `pragma: no cover` directives. They define coverage measurement and are
  not lint or type-check suppressions.
- Preserve runtime behavior, public APIs, file formats, and JAX compilation
  boundaries.
- Preserve the existing user-owned mode change in `docs/make.bat`.

## Baseline

- The repository contains 466 tracked Python files.
- There are 192 lint or type-check suppression markers in 75 tracked Python
  files.
- Ruff and BasedPyright are not configured in `pyproject.toml`.
- Ruff, BasedPyright, MyPy, and Flake8 are not installed in the execution
  environment.
- CI runs MyPy and repository conventions. Pre-commit runs Flake8 and repository
  conventions.
- The 192 directives consist of 130 MyPy ignores, 13 BasedPyright ignores,
  29 import-order ignores, 19 other `noqa` directives, and one file-level Ruff
  ignore.
- Most type ignores are concentrated in four repeatable cases: invalid-input
  tests, `ArrayLike` shape access, `brainstate.Module` construction, and nested
  decoded dictionaries.

## Tool configuration

- Add Ruff and BasedPyright to the `dev` optional dependency and
  `requirements-dev.txt`. Do not add runtime dependencies.
- Run Ruff over all tracked Python files. Use repository-wide settings for the
  supported Python floor of 3.11 and preserve the existing Flake8 gate.
- Run BasedPyright over `braintrace`, `examples`, `docs/diagnostics`, and
  `repo_conventions_test.py`. Keep test and optional-dependency settings
  explicit in configuration instead of file suppressions.
- Keep MyPy scoped to `braintrace` as configured. Removing suppressions from
  files outside that scope must not broaden MyPy's public API contract.

## Implementation

1. Configure Ruff and BasedPyright for the supported Python version and the
   repository's package and example layout.
2. Run Ruff, BasedPyright, MyPy, Flake8, and repository conventions to record
   the complete failure set.
3. Fix configuration-independent lint failures and remove lint suppressions.
4. Replace import-order suppressions with import-safe module structure. Keep
   registration imports and direct-script examples effective.
5. Fix type errors and remove type-check suppressions. Use typed invalid values
   in negative tests. Use explicit narrowing or casts only when a dependency
   exposes incomplete types and runtime narrowing cannot express the invariant.
6. Replace repeated private optimizer access with one small owned interface.
   Do not add a compatibility layer or silent fallback.
7. Add or update sibling tests only when a fix changes executable logic or
   corrects a defect.
8. Run focused tests for changed modules, then run every configured lint and
   type-check gate.

## Verification

Run these focused static gates before the relevant behavior tests:

```text
python -m ruff check .
python -m basedpyright
python -m mypy braintrace
python -m flake8
python -m pytest repo_conventions_test.py -q
```

Then run sibling tests for each behavior-bearing source edit. Run the complete
`braintrace` and `examples` suites only after the focused checks pass. Measure
coverage for changed behavior-bearing modules and keep meaningful coverage
above 90 percent.

## Acceptance criteria

- No Python file contains `noqa`, `type: ignore`, `pyright: ignore`, or a
  file-level Ruff suppression.
- Ruff reports no errors or warnings.
- BasedPyright reports no errors or warnings.
- MyPy reports no errors or warnings for its configured target.
- Flake8 reports no errors or warnings.
- Repository convention checks pass.
- Focused tests for behavior-bearing changes pass.
- No observed public behavior changes.

## Edge cases

- Negative tests must still pass values that exercise runtime validation.
- Imports used only to trigger registration must remain effective.
- Direct-script examples and package imports must both keep working.
- Optional dependencies and dependency APIs with incomplete type information
  must fail explicitly when unavailable.
- Test collection must not import unsupported optional backends.
