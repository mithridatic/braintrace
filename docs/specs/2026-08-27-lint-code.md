# Lint code

Status: proposed
Issue: BRA-116

## Purpose

Make lint checks pass without source-level suppression comments. Keep runtime
behavior, public interfaces, data formats, and compatibility unchanged.

## Baseline

- The repository has 466 tracked Python files.
- Seventy-five tracked Python files contain `noqa`, `type: ignore`,
  `pyright: ignore`, or `ruff: noqa` comments.
- The development requirements and CI workflow use Flake8 and mypy. They do not
  install or run Ruff or basedpyright.
- The current execution image does not contain the Python lint tools, so the
  first implementation step must make the requested checks reproducible.

## Scope

1. Add Ruff and basedpyright to the development lint toolchain and CI.
2. Define one explicit repository configuration for each new lint tool.
3. Remove Python lint and type-check suppression comments from tracked source,
   tests, examples, and documentation tools.
4. Fix each exposed diagnostic with direct imports, explicit types, casts,
   protocols, overloads, or smaller data flows as applicable.
5. Keep Flake8, mypy, repository conventions, and pre-commit checks passing.
6. Preserve the existing change in `docs/make.bat` and all other unrelated
   worktree changes.

## Constraints

- Do not replace source suppressions with equivalent file-level or
  configuration-level diagnostic exclusions.
- Do not weaken validation or convert explicit failures into fallbacks.
- Do not change JAX compilation boundaries or repeated-execution transforms.
- Do not use `jax.random`.
- Do not add runtime dependencies.
- Do not change intentionally invalid test cases. Express their invalid inputs
  with typed test helpers or casts when a static checker requires this.
- Preserve compatibility branches. Make their types explicit instead of
  deleting them.

## Implementation sequence

1. Add the lint tool versions and configuration. Run the tools to capture the
   complete baseline by rule and file.
2. Remove Ruff and Flake8 suppressions. Restructure imports and private access
   where needed.
3. Remove basedpyright and mypy suppressions from production code. Fix shared
   type boundaries before individual call sites.
4. Remove type suppressions from tests and examples with typed fixtures and
   explicit casts.
5. Run all configured lint and type checks. Run focused tests for every module
   whose executable code changes.

## Acceptance criteria

- A repository search finds no Python `noqa`, `type: ignore`,
  `pyright: ignore`, or `ruff: noqa` suppression comments.
- Ruff, basedpyright, Flake8, mypy, and repository convention checks complete
  with no errors or warnings.
- Focused tests pass for changed executable modules.
- Test coverage for changed behavior stays above 90 percent. Typing-only and
  import-order changes need existing focused tests, not artificial line tests.
- No observable behavior, public interface, persistence format, or wire format
  changes.

## Edge cases to verify

- Imports that must occur after a deliberate path setup still resolve when the
  import flow is made explicit.
- JAX and Brainstate compatibility imports still work on every supported
  version branch.
- Named tuple fields and method overrides retain their runtime names and call
  behavior.
- Array-like scalar inputs still fail or succeed at the same boundary.
- Tests that send invalid values still exercise the intended runtime errors.
