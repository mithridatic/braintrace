# Lint code

Status: approved
Issue: BRA-132

## Objective

Remove inline lint and type-check suppressions. Make the configured static checks
pass without a behavior change.

## Baseline

The repository has 192 inline suppression directives in 75 tracked Python
files:

- 68 directives in 28 `braintrace` files.
- 121 directives in 45 `examples` files.
- 3 directives in 2 `docs` files.

The repository configures mypy and Flake8. It does not configure Ruff or
basedpyright. Ruff, basedpyright, mypy, Flake8, and pytest are not installed in
the execution environment. The system Python installation also has no package
installer, so local verification is limited to checks in the standard library.

The worktree has an unrelated executable-bit change in `docs/make.bat`. This
issue must preserve that change.

## Scope

1. Add project configuration for Ruff and basedpyright in `pyproject.toml`.
2. Add the required lint tools to the development requirements.
3. Remove all tracked Python directives that suppress Ruff, Flake8, mypy,
   Pyright, or basedpyright diagnostics.
4. Fix each resulting diagnostic with a direct import, a narrower type, a cast,
   a small typed helper, or a clear data structure.
5. Keep tests that pass invalid values. Express deliberate invalid inputs with
   typed test helpers instead of suppression directives.
6. Keep the current mypy gate. Replace Flake8 with Ruff because Ruff covers the
   configured syntax and import checks in one project configuration.

## Behavior constraints

- Preserve public behavior, wire formats, persistence formats, and supported
  compatibility.
- Preserve explicit failures. Do not replace a failure with a fallback.
- Do not remove validation, correctness, provenance, or reproducibility checks.
- Do not change JAX compilation boundaries or repeated-execution drivers.
- Preserve `HiddenGroup` constructor defaults and named-tuple field metadata.
- Do not add source-code comments.
- Do not change unrelated worktree content.

## Verification

The change is complete when these checks pass with no warnings or errors:

1. Ruff check on all tracked Python files.
2. basedpyright on its configured project scope.
3. mypy on `braintrace`.
4. Ruff through the configured pre-commit hook.
5. Repository convention tests.
6. Focused sibling tests for each module whose runtime expression changes.
7. A repository scan that finds no inline lint or type-check suppression
   directive in tracked Python files.

The repository convention suite keeps the suppression scan as a permanent
gate for package, example, documentation, workflow-support, and root Python
files.

Meaningful coverage must remain above 90 percent for changed runtime modules.

## Implementation sequence

1. Establish tool configuration and record the complete diagnostic baseline.
2. Fix production-package diagnostics in small ownership groups.
3. Fix tests, examples, and diagnostics without weakening negative tests.
4. Remove obsolete compatibility and lint-only machinery when removal does not
   change behavior.
5. Run the focused checks, then run all configured static gates.

## Implementation evidence

The worktree removes all 192 inline lint and type-check suppressions from the
75 tracked Python files that contained them. It also adds Ruff and basedpyright
configuration, development dependencies, CI gates, a Ruff pre-commit hook, and
a repository convention test that prevents new inline suppressions.

The available focused checks pass:

- All 466 tracked Python files compile with the standard-library compiler.
- `pyproject.toml` parses with `tomllib`.
- All repository convention test functions pass when run directly.
- The isolated `HiddenGroup` metadata regression check passes for constructor
  defaults, `_field_defaults`, and field annotations.
- The isolated legacy-shim regression check passes for the original
  `ElemWiseOp.__call__` and `ElemWiseParam.execute` runtime signatures.
- The suppression scan returns no tracked Python matches.
- `git diff --check` reports no whitespace errors.

The module-initialization typing helper receives the bound
`super().__init__` method. This keeps dynamic superclass dispatch while giving
the type checker one narrow callable interface.

The legacy element-wise shims keep their original one-argument call signatures.
The lint fix must not widen those signatures or change positional and keyword
argument failures.

The execution image does not contain Ruff, basedpyright, mypy, Flake8, pytest,
pip, ensurepip, or the project runtime dependencies. The npm cache also has no
offline basedpyright package. The configured tool commands and the full test
suite cannot run in this image. The git index is read-only, so the worktree
changes cannot be committed here. The Paperclip API is also unavailable, so an
independent review task and issue status update cannot be created from this run.

## 2026-08-28 remediation update

Host validation reported 133 Ruff errors and 1,640 basedpyright errors after the
initial suppression removal. The runtime incident was separate from those
diagnostics.

This update removes the locally reproducible Ruff `E4` and `E7` findings. It
splits multiple imports and compact statements, removes statement semicolons,
replaces assigned lambdas with named functions, and replaces ambiguous
one-letter names. Exact-type checks still use exact type identity without a
direct `type(...)` comparison.

The execution image still has no lint or test tools. Network name resolution is
disabled, so `npx` and Ubuntu package downloads cannot supply them. Local
verification therefore remains limited to Python compilation, repository
convention tests, the suppression scan, a token-based check of the selected
Ruff `E4`, `E7`, and `E9` rule families, and `git diff --check`. Ruff,
basedpyright, mypy, pytest, and coverage remain required before review.
